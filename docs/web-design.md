# LabDuty 实验室值日与协同管理平台 — 前端设计与实现说明

> 本文档记录**参考设计稿（Apple HIG 风格设计系统）在本项目的落地实现**：
> 视觉体系取自参考设计稿（Apple HIG 风格），
> 业务数据与功能取自本项目真实规约表（11 人编制、14 日轮换、清扫规程）。
> **数据一律逐字引用原规约表，不作任何补写** —— 详见第 1.1 节「数据保真原则」。

---

## 1. 迁移原则

参考设计稿附带的交接规范明确要求：

1. **以导出稿为视觉契约**，而非自由再创作；冲突时优先匹配导出像素与行为。
2. **先冻结设计令牌再写组件**，禁止回落到框架默认主题色 / 字体。
3. **保留真实文案与数据**，不得用通用占位或营销填充词替换。
4. **保留交互可供性**：hover / focus / active / disabled / loading / empty / error / success。
5. **不保留原型阶段标注**（设计过程注释、预览标签）于产品 UI 中。
6. **响应式契约**：360×800 → 1920×1080 视口矩阵，均**不得出现横向滚动**。

本次实现严格遵循上述约定：令牌与组件样式**逐条迁移**，仅将参考设计稿中的占位数据（参考稿中的 7 人虚构占位成员与虚构设备台账）替换为本实验室的真实编制与职责。

### 1.1 数据保真原则（本项目最高优先级）

参考设计稿的槽位原本由「虚构设备台账（含型号、状态值、存储温度）」填充。**本项目不沿用这种填充方式**：
页面只允许出现以下两类内容，且不得混淆：

| 允许 | 说明 |
| :--- | :--- |
| **① 逐字引用** | 直接取自原始规约表的原文，不改写、不补充、不合并。包括：责任人分工「责任内容」栏、值日 roster「值日内容」与「频次」栏、区域打扫内容三份清单、轮换规则条款。 |
| **② 可核对的派生量** | 由原文计算得出、可逐项追溯的数值或日期。当前仅两类：当值人数（频次栏括号内数字，如 `(3)` → 3 人）、周期序号与日期区间。 |

**明确禁止**（本项目已据此清理，以下按类别描述，不再列举被删的具体数值以免误导）：

- ❌ 编造**设备 / 设施台账**（型号、存储温度、分区划法等）；
- ❌ 编造**状态值**（库存水位、容量百分比、液位百分比、到货状态等）；
- ❌ 编造**职务头衔**；
- ❌ 编造**交接备忘引语**；
- ❌ 编造**执行标准**（灭菌温度与时长、水质电阻率、水位线、压力区间等数值型规程）；
- ❌ 编造**分类标签**（对岗位 / 事项的臆造归类）。

> 判定方法：任一字符串若无法在原始规约表中逐字定位，即视为编造，必须删除或改为如实标注。

**无记载时的处理**：规约表未单列细分清单的岗位（①枪头与 ddH₂O 灭菌、⑨细胞房耗材补充、⑩⑪倒抽湿机水箱），
页面**如实显示「规约表未定义 / 未单列细分清单」**，并以原文的「值日内容」作为该岗位规程，而不是补写看似专业的内容。
所有引用处均带 **来源标注**（如「〈细胞房打扫内容〉第 3 项」「规约表「责任内容」栏原文」），便于逐条回溯核对。

### 交互与动效增强体系 (Motion & Micro-interactions)

1. **主题平滑过渡**：全站卡片、顶栏、文字与边框具备 `0.26s cubic-bezier(0.2, 0, 0, 1)` 平滑渐变，无视觉突变与白屏闪烁。
2. **卡片物理微升 (M3 Tonal Lift)**：悬停时微抬升 3px 并伴随对应色调的柔和弥散微光，视觉层次清晰。
3. **触控与按压反馈**：所有按钮与药丸胶囊在 `:active` 时具有 `scale(0.96)` 触控回弹反馈。
4. **视图切换流畅入场**：分段控件切换时执行 `m3FadeInUp` 物理减速入场（位移 14px + 淡入）。
5. **周期切换流动动效**：切换周期时网格触发 `cycle-pulse-anim` 微波动效，强化时间轴前进/回溯的感知。
6. **SOP 条目高光指示条**：鼠标悬停在 SOP 细则上时产生 3px 悬浮位移并在左侧点亮 Primary 品牌指示条。

## 6. 轮换引擎（业务核心）

- **基准**：Day 1 = **2026-10-12（10 月第 3 周周一）**，可在线重配置（10/12、10/19 或自定义）。
- **周期**：14 天 / 期，`offset` 可为负（筹备期，页面展示甲组初始排班）。
- **规则**：每 2 周**全员整体下移一格，末位补首位**（数组循环右移）。
- **正向映射**：`memberIndex = (slotId − offset mod 11 + 11) mod 11`
- **反向映射**：`slotId = (memberIndex + offset mod 11) mod 11`
- **闭环性质**：任一成员在 11 期内**恰好覆盖全部 11 个岗位**（已在测试中验证）。

## 8. 响应式契约与验证结果

以 Chrome DevTools Protocol 在真实渲染引擎中实测 **9 个视口 × 2 个视图 = 18 个组合**：

| 视口 | 尺寸 | scrollWidth = clientWidth | 顶栏高度 |
| :--- | :--- | :---: | :--- |
| mobile-compact | 360×800 | ✓ 无溢出 | 102px（2 行） |
| mobile-standard | 390×844 | ✓ 无溢出 | 102px（2 行） |
| mobile-large | 430×932 | ✓ 无溢出 | 102px（2 行） |
| foldable | 600×960 | ✓ 无溢出 | 102px（2 行） |
| tablet-portrait | 820×1180 | ✓ 无溢出 | 105px（2 行） |
| tablet-landscape | 1024×768 | ✓ 无溢出 | 105px（2 行） |
| laptop | 1366×768 | ✓ 无溢出 | **64px（1 行）** |
| desktop | 1440×900 | ✓ 无溢出 | **64px（1 行）** |
| wide | 1920×1080 | ✓ 无溢出 | **64px（1 行）** |

**结论：18 / 18 组合均无横向溢出**，满足「不得出现横向滚动」的契约；宽屏顶栏高度与参考设计稿 64px 完全对齐。

> 说明：成员胶囊条、轮换总览大表、11 期时间轴三处为**容器内横向滚动**（`overflow-x: auto`），不产生页面级横向溢出，属参考设计稿既有的设计行为。

## 9. 无障碍与语义

- 标题层级保持 `h1 → h2 → h3` 递进；
- 交互控件一律使用 `button` / `select` / `input` / `textarea`，保留可见聚焦态；
- 模态具备 `role="dialog"`、`aria-modal="true"`、`aria-labelledby`；
- Toast 使用 `role="status" aria-live="polite"`；
- 成员穿透、周期切换等均为真实 `button`，键盘可达；
- 所有动态插入的用户数据经 `esc()` 转义，避免 HTML 注入。
