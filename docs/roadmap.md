## R1. 试剂耗材即将告罄白板

- **业务依据**：原始规约表 —「其他非常用试剂耗材若即将告罄，请及时更新到白板上以便安排采购」。
- **模块定位**：执行层的**库存预警登记台**，把物理白板上的缺货手写记录搬到线上，并与固定责任人（订购分工）联动。
- **建议 UI 位置**：排班总览（Roster）底部支撑区，与「值日执行规约」并列；建议 2 栏布局。
- **数据模型**：

```js
{
  id: 's-<timestamp>',
  name: '15ml 离心管（无菌带刻度）',   // 物品名称与规格
  urgency: '急需 (库存 < 3 天)' | '预警 (库存 < 1 周)' | '常规补货',
  reporterId: 'M10',                // 登记人（BASE_MEMBERS.id）
  note: '细胞房已拆最后一包，请及时补订 2 箱',
  date: '10-07',
  status: '待采购' | '已采购'
}
```

- **交互与状态**：
  - 新增：模态表单（物品名称 `required` + 紧迫程度 + 登记人 + 补充说明）。
  - 列表：条目卡 + 紧迫程度胶囊（急需=危险红 / 预警=警示黄 / 常规=中性灰）。
  - 完成：`标记已采购` 将 `status` 置为已采购（或移出列表）；空状态提示。
  - 联动点：登记人下拉应默认当前聚焦成员；可进一步按固定分工自动 @ 对应责任人（如「细胞耗材→J.Y」）。
- **复用样式**：条目卡沿用 `.instrument-card-item` 结构；状态胶囊用 `--danger` / `--warn` 色调；
  模态沿用 `.modal-overlay` / `.modal-dialog` / `.form-*`；空状态需重建 `.empty-state`（虚线框 + 等宽小字）。
- **验收要点**：新增后列表即时刷新；刷新页面后数据仍在（localStorage）；打印时不出现（`.no-print`）。

## R2. 值日完成签名确认存根

- **业务依据**：原始规约表 —「每个人做完要签名确认」。
- **模块定位**：**执行留痕与可追溯台账**，为「每月第 1/3 周完成打扫」提供可核查证据链。
- **建议 UI 位置**：① 排班总览底部存根列表；② 成员 Duty 页「个人交接备忘」上方展示该成员个人存根。
- **数据模型**：

```js
{
  id: 'log-<timestamp>',
  time: '2026-10-06 17:30',
  cycle: '第 1 周期',
  cycleOffset: 0,                     // 建议补存周期序号，便于按周期筛选
  memberId: 'M01',
  duty: '各规格枪头灭菌烘干 / ddH₂O 灭菌',
  note: '各规格枪头各灭菌 4 盒，超纯水 5L 高压灭菌后入柜',
  status: '已签名确认'
}
```

- **交互与状态**：
  - 提交：模态表单（执行人 / 完成事项 / 备注）；完成事项下拉应与该成员**本周期岗位**联动预选。
  - 列表：按时间倒序，展示时间戳、周期、姓名、事项、备注、状态胶囊。
  - 空状态：「暂无签名确认存根 · 请在完成值日后签名」。
  - 增强项（可后置）：真迹签名（Canvas 手写）/ 导出 CSV 供实验室归档。
- **复用样式**：`.instrument-card-item` 或恢复 `.swap-request-item` 行式卡片；`✓ 已签名确认` 用 `--success` 胶囊。
- **验收要点**：存根与「成员 + 周期 + 事项」三者可对应；Duty 页能筛出该成员的存根。

## R3. 每周插枪头达标进度

- **业务依据**：原始规约表 —「每周每人插枪头 ≥ 10 盒，根据每种枪头消耗量灵活安排枪头类型」。
- **模块定位**：**周度量化指标看板**，为「每周每人 ≥10 盒」这一硬性配额提供进度可视化与计数入口。
- **建议 UI 位置**：① 排班总览底部 11 人进度总览（带 `重置本周`）；② 成员 Duty 页个人进度条（带 `+/-` 步进）。
- **数据模型**：

```js
// 键：成员 id，值：本周已插盒数
{ M01: 6, M02: 8, M03: 10, /* … */ }
// 建议补充：周标识，用于自动跨周归零
{ week: '2026-W41', counts: { M01: 6, /* … */ } }
```

- **交互与状态**：
  - 进度条：`--accent` 填充；达标（≥10）切换为 `--success` 并显示 🎉。
  - 计数：`+/-` 步进按钮（`aria-label` 完备），最小值为 0。
  - `重置本周`：将全员归零并给出 Toast 反馈。
  - 增强项：按周自动归零（避免手工重置）；按枪头规格（10μl / 200μl / 1000μl）分项计数。
- **复用样式**：进度条 = `--surface` 轨道 + `--accent`/`--success` 填充（圆角 `--radius-pill`，高度 7px）；
  步进按钮 = 24×24、`--radius-sm`、边框 `--border`。
- **验收要点**：11 人进度条与计数数值一致；达标态与未达标态视觉可区分。

## 重新引入时的实施顺序建议

1. **先定口径**：明确签名/白板的记录粒度（按人？按岗位？按周期？）与是否需要纸质双轨。
2. **R3（插枪头）** 最简单、无跨人依赖 —— 可作为第一个恢复项，验证存储层与进度组件。
3. **R2（签名存根）** 依赖 R3 验证过的存储与列表组件；随后接入 Duty 页个人视图。
4. **R1（告罄白板）** 建议与「固定责任人分工」联动（自动指向该项耗材的责任人），因此放最后。
5. 每恢复一项，**同步**：`docs/web-design.md` 的架构图/交互状态表、`docs/lab-duty-roster.md` 的对应条款说明。

## 通用技术准备（已在代码中保留）

- 安全存储封装 `LS`（`file://` 源或隐私模式下自动降级为内存态）与通用 `readJSON(key, fallback)` 均**未移除**，恢复时直接复用。
- 存储键命名约定：`labduty_<模块>_v<n>`；恢复时建议用 `v4` 以区分旧数据。
- 打印媒体已统一隐藏 `.no-print`、`.btn`、`.toast-pill` 等控件，恢复交互控件时请标注 `.no-print`。
- 无障碍约定：模态 `role="dialog"` + `aria-modal` + `aria-labelledby`，步进按钮提供 `aria-label`。
